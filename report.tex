\section{Introduction}

This project addresses the security of a central student records environment serving two campuses. The security review identified risks related to weak staff passwords, unencrypted file transfers, outdated software, guest network access, and repeated connection attempts from an unfamiliar external address.

The project focuses on risk assessment, encryption, file integrity verification, and network traffic filtering. A small Python security toolkit was developed to demonstrate encryption, decryption, verification, and SHA-256 integrity checking.

\section{Encryption and Integrity Toolkit}

\subsection{Implementation}

The Python security toolkit uses the Fernet implementation provided by the \texttt{cryptography} library for symmetric authenticated encryption.

The encryption key is generated locally and stored outside the GitHub repository. The key is therefore not included in the project repository.

The program performs the following operations:

\begin{enumerate}
    \item Encrypt the sample student record.
    \item Decrypt the encrypted file.
    \item Verify that the decrypted file matches the original.
    \item Calculate and compare SHA-256 hashes to detect subsequent changes.
\end{enumerate}

\subsection{Encryption Test}

The encryption test produced the following result:

\begin{verbatim}
File encrypted successfully: student_record.encrypted
\end{verbatim}

This confirms that the sample student record was successfully encrypted.

\subsection{Decryption and Verification Test}

The program then decrypted the encrypted file and compared it with the original record.

The result was:

\begin{verbatim}
File decrypted successfully: student_record_decrypted.txt
Verification successful: decrypted file matches the original.
\end{verbatim}

This demonstrates that the encrypted file could be successfully decrypted and that the decrypted contents matched the original sample record.

\subsection{SHA-256 Integrity Test}

A baseline SHA-256 hash was created for the student record.

The baseline hash was:

\begin{verbatim}
30bb1a5da6b9dd2252e8be240bfd1cc259030e28e0e12cb8c7caaff1be12c71c
\end{verbatim}

After the student record was subsequently changed, the program calculated the following hash:

\begin{verbatim}
0fbaac00d585c7a38b1803473158297bed55cc5d2c9681bcdc464245d58207e1
\end{verbatim}

The hashes were different, so the program detected the modification and reported:

\begin{verbatim}
Integrity check failed: file has changed.
\end{verbatim}

This demonstrates that SHA-256 comparison can detect changes made to a file after a trusted baseline hash has been created.

\subsection{Invalid Input Handling}

The security toolkit checks whether required files exist before performing encryption, decryption, hashing, or verification.

If a required file is missing, the program reports an error instead of crashing. This provides basic error handling for invalid or missing inputs.

\section{Network Traffic Filtering}

\subsection{Required Firewall Controls}

The assessment requires the following network controls:

\begin{enumerate}
    \item Block guest network access to the student records server.
    \item Permit authorised staff network access to the service specified by the assessor.
    \item Block other inbound access to that service.
\end{enumerate}

These controls are intended to restrict access to the student records environment according to authorised network sources.

\subsection{Firewall Testing Plan}

Three connection tests are required:

\begin{enumerate}
    \item Test an authorised staff connection to the specified service. The expected result is that the connection is permitted.
    \item Test a guest-network connection to the student records server. The expected result is that the connection is blocked.
    \item Test a connection from another unauthorised source to the protected service. The expected result is that the connection is blocked.
\end{enumerate}

The exact firewall and connection-testing commands depend on the operating system and firewall technology used in the authorised laboratory.

The detailed testing procedure is recorded in \texttt{filter\_tests.md}.
